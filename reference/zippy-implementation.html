Zippy implementation map

Use the visible behavior to choose a starting file. The browser handles presentation, FastAPI coordinates workflows, and the Shopee simulator supplies catalog and checkout data.

Where to look

Chat and cards
requestReply and applyReply bind the UI to the event stream. readEvents decodes NDJSON and cards adapts payloads for display. app.js · services.js
Routes and workflow
create_app wires dependencies and scopes requests to a visitor’s service. Zippy owns session state, scripted branches, order and booking rules, and event publication. main.py · service.py
Coach and prompts
AgentsCoach.stream calls the model-backed coach with tools for reading health context and emitting selected cards. Prompts validates required YAML placeholders at startup. integrations.py · prompts.yaml
Eye mask checkout
buy prepares an unpaid order using the previously compared product ID. payment_url requests the simulator’s approval page. Ploy enters her PIN there. order_status checks the simulator’s status and emits the receipt and reminder. Workflow · Shopee tools · Simulator HTTP routes
Dinner and reservations
proactive prepares the dinner moment. The shop listings come from Shopee Food. After Ploy agrees, book creates the booking and the phone adapter handles the call. finish_call publishes the outcome and determines the follow-up. The backend can use a demo adapter or Twilio for configured live demo calls. Dinner and booking flow · Phone adapters and media bridge
Notifications and reminders
emit persists feed items with increasing IDs. The browser polls for items after its last ID. For a notification with a subscribed device and push configured, the backend can also send Web Push. The backend checks for due reminders in its lifespan task. Feed and reminders · Scheduler and feed route · Service worker
Visitor data and meal photos
VisitorStores opens guest-scoped stores, using MongoDB when configured and JSON locally otherwise. put_persona imports health history and updates the profile. scan_meal uses a photo adapter and persists the estimate. For stored photos the backend retains the object key and signs a URL on read. Storage · Import and upload routes · History mapping
Presenter recommendations
The presenter can request a food or item recommendation for a guest. RecommendationAgents builds candidates from the food catalog or recent wellness signals, then queries the relevant Shopee tools. Zippy.recommend publishes the cards through the feed. Architecture map · Bucket keys and fallback rules

How the code grew

The Git log shows the demo spec first, then the Shopee simulator and backend workflows, then the browser chat. Guest sessions, dashboards and presenter controls followed. Later commits added history import, meal photo logging and web push.

git log --first-parent --reverse --oneline

Compare that history with the intended build order. For example, the spec describes a cron job calling /proactive. The checked-in cron script currently only prints a timestamp. The backend implements /proactive and presenter-triggered moments separately. Trigger routes

Three terms worth remembering

NDJSON
One JSON object per line. A chat response can carry text fragments, cards and quick replies as they become available.
Feed
Persisted events such as a proactive insight, a booking update or a receipt. Polling with after fetches newer items.
MCP
Model Context Protocol. Zippy’s backend uses it to call named tools on the separate Shopee simulator.
