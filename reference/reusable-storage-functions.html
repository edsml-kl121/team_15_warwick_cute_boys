Reusable storage functions

Choose the helper based on the data you need and whether you need to read, persist or sign it.

Fresh profile, persona and meals for one day
read_guest_recommendation_data(database, owner, day) performs synchronous MongoDB reads. Supply the authenticated guest ID and the configured database. It returns the guest’s profile, persona and meals dated that day, or None when the guest is absent. The async context loader runs it with asyncio.to_thread. MongoDB helper · Async caller
Recommendation context from both stores
await load_recommendation_context(visitor, bucket, food=True, database=...) merges stored and current meals by ID, loads a bucket persona if needed and returns (profile, persona, wearable, logged, day). Use food=False for the item path. The food catalog is loaded by a separate read. Context loader and callers
Persist existing guest state
Use zippy.store.save() through the guest-scoped service. VisitorStores.open chooses the backend. The put_persona route shows how to use Depends(service) and take zippy.mutation around a state update. Guest API pattern · Persistence
Load JSON from the S3-compatible bucket
await data.read(key) on BucketRecommendationData calls S3 get_object, parses JSON and caches it for five minutes. The FastAPI startup code wires the adapter into app.state.recommendations.data. Reader · Startup and route usage
Display a private image
MealPhotos.url(key) signs an uploaded meal photo URL. await data.catalog_image_url(food_id, dish) looks up a catalog image, validates its bucket path and signs the URL. Meal photos · Catalog images
Upload a meal photo
await MealPhotos.read(image, key) prepares the photo, runs nutrition estimation and calls S3 put_object when a bucket is configured. This helper is for the meal scan workflow. Photo scan and storage
