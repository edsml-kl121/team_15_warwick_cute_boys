Recommendation data sources

Both presenter agents refresh guest data from MongoDB when available. The food agent also reads the S3 food catalog.

Which reads happen

Both agents first load guest context
load_recommendation_context refreshes the profile, persona and meals through read_guest_recommendation_data when MongoDB and a guest ID are available. If the resulting context has a persona, no bucket persona lookup is needed. Context loader · MongoDB query
Both agents, if history is missing and a bucket is configured
Read body_data/user_profiles.json for a unique case-insensitive display-name match. List the personas/<persona_id>_ prefix, read the matching JSON and body_data/body_health_wearable.json, and keep the relevant persona rows. Bucket lookup
Food agent
On the bucket persona path, also read body_data/food_history_log.json. With either persona source, read body_data/food_db.json for meal candidates and then query Shopee Food for similar dishes. The food route returns 503 if bucket access is required and unavailable. Food branch · Error mapping
Item agent
Use recent sleep or activity signals to choose a search term, then query Shopee Mall. In Ploy demo mode, an empty wearable summary can fall back to demo sleep. The agent can offer a general suggestion when no signal qualifies. An S3 read error returns 503 if a configured bucket persona lookup fails. Item branch · Error mapping

Check a deployment

  1. Identify the revision running on the correct Railway backend.
  2. Check whether the backend’s S3 variables reference the bucket that contains the dataset. Check that its credentials allow reading the expected keys and listing the persona prefix. Configuration
  3. For evidence of the bucket persona path, use a designated demo guest with a unique matching bucket display name and no imported persona. An item recommendation based on imported history or demo sleep can succeed without a bucket read. A food recommendation exercises the catalog path even when the guest imported their history.
