Lesson 4 · 6 minutes

Trace both recommendation agents

After this lesson, you’ll be able to point to where a recommendation is selected, where its listings come from, and how it reaches the guest’s chat.

Follow a presenter click

The presenter sends agent: "food" or agent: "item". FastAPI checks the presenter key, finds the matching guest sessions, and calls Zippy.recommend for each guest. RecommendationAgents.run loads guest context before dispatching to the requested branch. Presenter buttons · Trigger route · Agent entry point

Food chooses a dish

food_candidates ranks meals from MongoDB using the guest’s goals, meal history, and preferences. choose selects a dish. A later request for nearby places calls Shopee Food. Food branch

Item chooses a search term

item builds search options from recent wearables, such as an eye mask after short sleep. choose selects a search term. Shopee Mall then returns specific products, which the backend sorts for comparison. Item branch

The optional model chooses from the supplied shortlist by returning an index. If no model is configured, choose returns the first candidate. After the branch returns, Zippy.emit saves the recommendation to the session feed. The browser polls that feed and renders the cards. Choice logic · Publishing · Feed polling

Find the owning layer

In the food flow, where does a restaurant’s listed price come from?

Who makes an item from the comparison card available to the Buy route?

Answer key

Shopee Food supplies the restaurant price. Zippy.recommend makes returned item IDs available to Buy by storing the products in the session.
