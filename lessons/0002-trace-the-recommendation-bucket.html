Trace the recommendation bucket

Predict which storage calls happen when the presenter clicks Recommend food or Recommend an item.

Follow the branch

  1. Startup. FastAPI selects RECOMMENDATION_BUCKET or falls back to S3_BUCKET. It uses the configured S3 endpoint and can reuse the meal-photo S3 client when the bucket matches. Startup code · Railway variables
  2. Presenter click. POST /presenter/trigger receives a guest name and an agent of food or item. The backend chooses the guest’s latest chat and runs the corresponding branch. Presenter controls · Route
  3. Persona. load_recommendation_context starts with guest state and refreshes the guest’s profile, persona and meals from MongoDB when available. If no persona is available, the configured bucket adapter looks for a unique display-name match in the dataset. Read load_recommendation_context
  4. Food or item. Food always needs the bucket catalog body_data/food_db.json. Item uses wearable signals from the selected persona. It can use demo sleep in Ploy mode, or offer a general suggestion when there is no qualifying signal. Shopee MCP supplies the restaurant listings or products. Read food and item

The bucket adapter reads JSON via get_object and caches each successful object read for five minutes per backend process. Two requests can use the same JSON with only one object download. Read BucketRecommendationData.read

Predict the source

A guest imported their history. What still comes from the bucket when you run the food agent?

An imported persona has recent short sleep. Where does the item agent get its sleep signal?

Answer key

The food catalog and the imported persona. The condition in load_recommendation_context controls persona lookup. The catalog read lives inside food.

Use the test to tell what’s proven

Open test_presenter_agents_use_guest_data_and_publish_search_results. Its fake bucket implements get_object and list_objects_v2. Predict why Krit’s 5.5 hours appears in the item recommendation even though another persona has 15 hours, then read the persona ID filter to check. A passing test confirms the code follows the intended data path. A deployed read also depends on which code is running, the service’s bucket settings, and the objects it can access.
