Call the recommendation API

Choose the route based on who initiates the recommendation and whether they want a meal, nearby places, or an item.

One presenter route for both agents

Both presenter buttons call POST /api/presenter/trigger with the presenter key. The agent field selects the workflow. FastAPI runs it for each matching guest and publishes the result to their feed. Browser call · Presenter handler

{"guest_name":"Ploy","agent":"food"}
{"guest_name":"Ploy","agent":"item"}

Zippy.recommend is the shared backend method. It calls RecommendationAgents.run, which reads the current guest from MongoDB and dispatches to the selected branch. Food ranks catalog meals and saves a meal for a follow-up search. Item uses wearable signals to pick a search query, calls Shopee Mall, and stores the comparison’s product IDs for Buy. Shared service · Agent branches

The guest’s food and history routes

  1. POST /api/recommendations/food with {"session_id":"my-chat"} creates and posts a meal card. This calls the same food branch as the presenter.
  2. POST /api/recommendations/food/places with that same session ID runs Shopee Food for the pending dish. Add location with lat and lng to search near the current location outside demo mode.
  3. GET /api/recommendations/health-history reads the guest’s history. Add inclusive start and end dates to select up to 90 days.

Guest calls use the session cookie. To trigger an item recommendation over HTTP, use the presenter route with agent: "item". Primary reading · HTTP contract · Guest handlers
